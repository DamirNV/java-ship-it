
# Java ShipIt — симулятор доставки посылок

**Java ShipIt** — учебное консольное приложение для моделирования службы доставки.

Программа позволяет добавлять отправления разных типов, рассчитывать стоимость доставки, распределять посылки по коробкам с ограничением веса, проверять сроки годности и имитировать отслеживание отправлений.

Это **структурно доработанная версия** моего раннего проекта [Java Delivery Simulator — ShipIt](https://github.com/DamirNV/java-delivery-simulator).

Основная бизнес-логика и функциональность сохранены. Изменения затрагивают прежде всего организацию исходников, тестов и инфраструктуру репозитория.

## Чем отличается от предыдущей версии

- Исходники перенесены в пакет `ru.yandex.practicum.delivery`, а классы предметной области — в подпакет `parcels`.
- Тесты организованы в отдельном каталоге `test/ru/yandex/practicum`.
- Приведено к стандартному стилю имя тестового класса `CalculateDeliveryCostTest`.
- Добавлен GitHub Actions workflow для pull requests на основе повторно используемого workflow Яндекс Практикума.
- В консольном сценарии добавлен разделитель после ввода дня отправки.

Это не новая система доставки и не переписывание бизнес-логики с нуля. Обе версии сохранены для демонстрации развития организации Java-кода.

## Возможности

- Добавление стандартных, хрупких и скоропортящихся посылок.
- Расчёт стоимости доставки в зависимости от веса и типа отправления.
- Размещение отправлений в коробках с ограничением суммарного веса.
- Просмотр содержимого коробок.
- Имитация упаковки и доставки.
- Вывод сообщений о местоположении хрупких посылок.
- Проверка сроков годности скоропортящихся отправлений.
- Интерактивное консольное меню.

## Технологии

- Java Core
- ООП: абстрактные классы, наследование, интерфейсы и полиморфизм
- Дженерики: `ParcelBox<T extends Parcel>`
- Коллекции: `ArrayList`, `List`
- JUnit 5 — 12 тестовых методов
- GitHub Actions

Проект не использует Spring, базу данных, Maven или Gradle.

## Как запустить

**Требования:** установленный JDK. Компиляция и запуск приложения проверены на Java 21.

### Через IntelliJ IDEA

1. Откройте репозиторий в IntelliJ IDEA.
2. Укажите установленный JDK.
3. Запустите метод `main()` класса `ru.yandex.practicum.delivery.DeliveryApp`.
4. Выберите действие в консольном меню.

### Через терминал (Linux/macOS)

Из корня проекта:

```bash
javac -encoding UTF-8 -d out/classes \
  src/ru/yandex/practicum/delivery/parcels/*.java \
  src/ru/yandex/practicum/delivery/DeliveryApp.java

java -cp out/classes ru.yandex.practicum.delivery.DeliveryApp
```

## Тестирование

В проекте есть **12 тестовых методов JUnit 5** в трёх классах.

Они проверяют:

- Добавление посылок с учётом ограничения веса.
- Определение просроченных отправлений.
- Расчёт стоимости доставки для разных типов посылок.

Для запуска тестов в IntelliJ IDEA необходимо подключить JUnit 5 и обозначить каталог `test` как Test Sources Root.

GitHub Actions workflow запускается при pull requests и использует внешний workflow Яндекс Практикума. Это не самостоятельно разработанная CI-система.

## Ограничения

- Нет полноценной проверки некорректного ввода.
- Отправка и отслеживание моделируются выводом сообщений в консоль.
- Данные не сохраняются после завершения программы.
- При превышении лимита коробки посылка всё равно добавляется в общий список отправлений.
- Для срока годности используются условные номера дней.
- В исходном репозитории присутствуют скомпилированные файлы, которые желательно убрать из Git.
